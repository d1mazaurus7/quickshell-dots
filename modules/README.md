# Модули бара: как добавить новый

Бар строится из реестра `shell/bar/BarModules.qml`: блоки «Слева / Посередине / Справа»
читают id модулей из `Config.options.bar` (`left`, `center`, `right`), а раздел настроек
«Бар» (`settings/pages/BarPage.qml`) показывает все модули реестра. Отдельно регистрировать
модуль в настройках не нужно: запись в реестре сразу добавляет его в список раздела «Бар».

## 1. Модуль

Создай `modules/<name>/<Name>.qml`. Корень — визуальный элемент (`Item`, `Rectangle`, `Text`…)
с собственными `implicitWidth` / `implicitHeight`: блок бара — это `RowLayout`, он берёт размеры
модуля из них.

```qml
import QtQuick
import "../../shell/theme"

// Короткое описание модуля
Item {
    id: root

    // Высота бара — модуль сам решает, какой высоты его кнопка
    property real barHeight: 40

    implicitWidth: label.implicitWidth + Tokens.spacingLarge * 2
    implicitHeight: barHeight - Tokens.scaled(12)

    // Модуль может скрываться сам: в RowLayout скрытый элемент не занимает места
    // visible: ...

    Text {
        id: label
        anchors.centerIn: parent
        text: "..."
        color: Tokens.colors.on_surface
        font: Tokens.fontMedium
    }
}
```

Правила:
- Цвета, отступы, скругления, шрифты и длительности анимаций берутся только из `Tokens` (см. AGENTS.md → Visual).
- Системное состояние и IPC выносятся в отдельный файл модуля (как `volume/VolumeState.qml`),
  визуальный компонент только отображает это состояние.
- Модуль ничего не знает о реестре и о том, в каком блоке бара стоит.
- Если в папке модуля есть `qmldir`, в нём должны быть перечислены **все** типы, которые
  импортируются снаружи. Иначе при импорте папки появится ошибка `X is not a type`.

## 2. Регистрация в баре

В `shell/bar/BarModules.qml`:

1. Импорт:
   ```qml
   import "../../modules/<name>" as MyModule
   ```
2. Компонент. Корневой тип — сам модуль. Компонент обязательно объявляет
   `required property var bar` и переводит его в параметры модуля:
   ```qml
   Component {
       id: myModule
       MyModule.MyModule {
           required property var bar
           barHeight: bar.implicitHeight
       }
   }
   ```
3. Строка в `list`. Порядок строк = порядок в списке неразмещённых модулей в настройках:
   ```qml
   { id: "myModule", title: "Мой модуль", component: myModule },
   ```

`id` — ключ, под которым модуль хранится в `settings.json`. Он должен быть уникальным и не
должен меняться: если его переименовать, у пользователя модуль пропадёт с бара (неизвестные
id пропускаются).

### Что есть в `bar`

`bar` — окно бара (`PanelWindow` в `shell/Shell.qml`, по одному на экран):

| Свойство                | Что это                                         |
|-------------------------|-------------------------------------------------|
| `bar.implicitHeight`    | высота бара                                     |
| `bar.modelData`         | экран (`ShellScreen`); имя выхода — `bar.modelData.name` |
| `bar.stopwatch`         | общий секундомер                                |
| `bar.musicModule`       | модуль плеера, если он стоит на баре, иначе `null` |
| `bar.toggleMusicPlayer()` | открыть/закрыть окно плеера                   |

Если модулю нужен общий объект из `Shell.qml` (состояние, окно, IPC), добавь в `barWindow`
свойство `readonly property var <имя>: <id объекта>` и используй его как `bar.<имя>`.
Не создавай общее состояние внутри компонента модуля: на каждом экране создаётся свой
экземпляр модуля, а при каждой перестановке модулей в настройках экземпляры пересоздаются.

## 3. Где модуль появится

- **Новый модуль сначала не стоит на баре.** Он появляется в разделе настроек «Бар» в верхнем
  списке, и пользователь сам перетаскивает его в нужный блок.
- Чтобы модуль стоял на баре по умолчанию, добавь его id в дефолты секции `bar` в
  `shell/config/Config.qml`. Дефолты действуют, только пока в `settings.json` нет ключей
  `bar.left` / `center` / `right`, поэтому при уже сохранённой раскладке модуль всё равно
  окажется в списке неразмещённых.
- Раскладку меняют только присваиванием нового массива (`Config.options.bar.left = [...]`).
  `push` / `splice` по самому свойству не сохраняются.

## 4. Настройки самого модуля (по желанию)

Расположение модуля задаётся в разделе «Бар». Собственные параметры модуля (стиль, формат и т.п.)
оформляются отдельно:

1. Секция `property JsonObject <module>: JsonObject { ... }` в `shell/config/Config.qml`
   (см. `shell/config/SETTINGS_README.md`).
2. Страница `settings/pages/<Name>Page.qml` и строка в `sections` + `Component`
   в `settings/SettingsWindow.qml` (см. `settings/SETTINGS_WINDOW_README.md`).
3. В модуле параметры читаются привязками: `Config.options.<module>.<ключ>`.

## Проверка

Работающая оболочка перечитывает изменённые `.qml` сама. После изменения файлов:

```sh
qs log | tail -30
```

Правка одного `qmldir` перезагрузку не запускает: после неё сохрани любой `.qml`
(например, `touch shell/Shell.qml`).

Затем открой настройки → «Бар» и проверь:
- модуль есть в списке;
- его можно перетащить в каждый блок и вернуть обратно в список;
- он корректно отображается на баре на всех экранах.
