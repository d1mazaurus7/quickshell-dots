# Project

Персональная оболочка на Quickshell/QML для Niri.
Все ответы и пояснения — на русском.

## Environment

- OS: NixOS 26.05.
- Wayland compositor: Niri 26.04 (Nixpkgs).
- Quickshell revision: 4f508be500dea6e5732cc3d50382a0048b17e7b1.
- Quickshell source: Official-Nix-Flake.

Эти версии — целевое окружение.

## Структура
- shell.qml — точка входа, только Shell {}.
- shell/Shell.qml — корень (ShellRoot). Для каждого экрана он создаёт окно Bar.
- shell/theme/Tokens.qml — singleton с общими токенами: цвета из Palette, отступы, скругления, шрифт, длительности анимаций.

## Visual

- Общая стилистика: Material Design.
- Единственный источник цветовой палитры — matugen.
- Конфигурация matugen: ~/.config/matugen/.
- Не добавляй независимые темы, переключатели тем и
  захардкоженные UI-цвета без запроса.
- Используй общие токены цветов, типографики, отступов,
  скруглений и длительности анимаций.
- Анимации должны быть плавными, мягкими и короткими,
  без задержки реакции интерфейса.
- Предусматривай состояния hover и pressed у интерактивных
  элементов, где это уместно.
- Не меняй конфигурацию matugen без согласования.

## Scope and workflow

- Реализовывай только запрошенные функции.
- Перед редактированием прочитай относящиеся к задаче файлы.
- Расширяй поиск по проекту только при необходимости.
- Предпочитай минимальные рабочие изменения.
- Не выполняй несвязанный рефакторинг.
- Следуй существующей структуре и стилю проекта.
- Отделяй визуальные компоненты от системного состояния и IPC.
- Не создавай абстракции и зависимости «на будущее».
- Не добавляй зависимости без согласования.
- Для небольшой задачи сразу выполняй изменение.
  Для крупных или неоднозначных изменений сначала предложи план.

## Verification

- После изменения выполняй доступные проверки,
  относящиеся к изменённым файлам.
- При возможности безопасного тестового запуска проверяй
  ошибки выполнения Quickshell.
- Не запускай второй экземпляр оболочки вслепую:
  сначала уточни способ изолированного запуска.
- Не утверждай, что внешний вид, анимации или поведение
  проверены, если визуальная проверка не выполнялась.
- Если проверка недоступна, укажи причину и шаги
  для ручной проверки.
- При повторении одной ошибки не продолжай однотипные
  попытки вслепую: обратись к документации и референсу.
- В конце кратко укажи:
  что изменено, что проверено и что осталось проверить.
